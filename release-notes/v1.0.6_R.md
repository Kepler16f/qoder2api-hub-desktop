# 1.0.6_R — 账号保护与排队治理 + 并入上游 v1.5.6–v1.6.1（网关 2026.10.20.2_re–2026.10.22.2_re）

自 v1.0.5_R 以来的全部改进一次搭载：核心是**排队不再误伤账号池**（#71 / #69）与**出站体积护栏**（#59），外加智能体配置修复（#53）与计费配额分级（110）。

## 🔧 排队与账号保护

- **排队语义治理**（上游 #71 / #69 fork 缝合）：上游排队超预算后返回 HTTP 403 + 10605 是**模型级**排队——不再冷却账号、不解绑会话亲和、不判死单号池（此前面板看起来就像「Key 失效」）；排队计数按**请求**计预算；排队耗尽且另一区同模型有就绪账号时**跨区 failover**；最终统一 `429 + Retry-After`（客户端收到「稍等 N 秒」而不是误导性 403）。
- **请求级故障不再冷却全池**（上游 #65）：内容审核 / 参数非法 / 上游 413 这类换号无意义的错误，不换号不冷却，原错误直接抛给客户端；全池同样失败（断网/上游整体故障）不再逐号记账——熔断延迟到「同一请求换号成功」才落账，网络恢复即自动可用。（fork 在该分支的 raise 前补了账号信号量释放，防误锁 10 分钟。）
- **110 日计费配额分级**（fork 2026.10.20.2_re）：账号×模型当日配额超限（HTTP 403 + code 110）模型级长冷却起步、两模型连撞升级账号级；不刷令牌、允许换号重开；CN 设备族刷新回显过期 `expiresAt` 钳位 24h（消除每次选号同步刷令牌）。
- **#55 之后 · 信封层排队等待**（v1.5.5 延续）：HTTP 200 建流后 SSE 信封投递排队时按 `retryAfterSeconds` 等待并重试。

## 🧲 并入上游 v1.5.6–v1.6.1（2026.10.22.1_upstream · 27 提交 · 9 个版本）

- **#59 出站体积护栏**：多模态请求不再把整份 Base64 重复塞进两处冗余字段（体积 3 倍膨胀 → 超 SLB 30MB 被 RST → Broken pipe 被当瞬态重试 → 全池熔断）；超 `QD_MAX_BODY_MB`（默认 29MB）在发请求**前**直接 413。同批：#60 工具回声抢救式解析、#58 模型清单磁盘缓存 + `/models/refresh`、#57 容器反代国际版告警。
- **#72 残缺工具回声 fail-closed**：声明了 tools 却只回一个 marker 时不再静默吞掉按 stop 收尾（coding agent 会误判任务完成）——改抛 `EmptyToolEcho`，四条协议出口统一 fail-closed，客户端据此重试。
- **#53 智能体一键配置修复**（⭐ 自 v1.0.4_R 起随桌面版出手的 bug）：Key 下拉 value 恒为空导致「一键配置」根本发不出请求；改为 key id + 点击时取明文。
- **#70 排程可配置 + 到点即补**：签到/保活时刻面板可改（5 段 cron、24 小时刻度圆环、账号间隔抖动）；旧实现整点轮询会因时区偏差整段漏（修「签到无效」）；v1.6.1 修 `/scheduler/config` 404。
- **#61 出站身份对齐**：UA 按区取官方 `QoderWork/1.1.64` / `Qoder/1.1.64`、请求 id 纯随机、设备码 UUIDv4 形状——防被动聚类成「网关特征」。
- **#67 组织共享池**：同组织多账号共享额度按 `organization_id` 去重（此前 5 号把 100 万乘成 400 万）；`cap: -1` 无限池显式语义。
- **#62 / #63 / #56 / #66-#68 / #74**：Anthropic adaptive thinking 档位映射（Claude Code effort 四档）；`namespace`/`web_search` 工具类型上游前过滤；团队闸门默认 auto（非团队号不生效）；模型文案快照重写 + `QD_OFFICIAL_TEXT` 覆盖；账号/API Key 备注持久化与回显。
