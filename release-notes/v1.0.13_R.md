# 1.0.13_R — 路由工作台与管理台 + Claude Code 大请求修复（网关 2026.11.07.1_upstream–2026.11.09.1_upstream）

自 v1.0.12_R 以来的全部改进：并入上游 v1.9.2–v1.9.4 与 v1.9.1 之后的全部修复。新增**面板管理台与路由工作台**，修好 Claude Code 大请求体 400，并让账号额度显示按「个人 + 共享」合并口径呈现。

## 🧭 面板管理台 + 路由工作台（v1.9.0 / v1.9.4）

- **本地管理台**（面板内可达，密码鉴权）：账号与档位路由的统一工作台，配置改动即时生效；
- **档位路由**：可按模型指定账号分组与优先级，网关按路由结果选号（未配置时行为与从前完全一致）；
- **面板视觉重构**（v1.9.4）：登录转场（景深虚化 + 缩放溶解）、滚动预触发（视口外提前渲染，消除「慢半拍」）、全站下拉/复选框/滚动条样式统一、图表交互重做；
- fork 侧确认：桌面客户端设置区与局域网访问区块在重构后**逐符号存活**（托盘、开机自启、客户端设置组、局域网开关与 IP 展示全部在位），登录后流程同时保留上游的转场等待与 fork 的「会话过期后重建轮询定时器」。

## 🐛 Claude Code 大请求体 400 修复（v1.9.3，PR #148）

- **现象**：Claude Code（undici）在长消息/大图/复杂工具上下文时改用 `Transfer-Encoding: chunked` 发 `/v1/messages`，网关只按 Content-Length 读 → 请求体判空、误报 **400 "messages is required"**，未消费的 chunk 帧还会在 keep-alive 连接上被当成下一条伪请求（日志大量 Bad request syntax）。
- **修复**：新增分块体读取（解析块大小与数据、吃可选 trailer 与 CRLF 终态），超限时安全关闭连接；`_read_payload()` 按 Transfer-Encoding 分支。

## 💭 Anthropic thinking block 多粒度配置（v1.9.3，#146）

- 可按 **Key / 面板 / 环境变量** 三级粒度配置 thinking block 的输出策略；**默认空 = 跟随原有行为**，不改变现有客户端拿到的内容。
- 补充了「何时可以安全启用 empty 模式」的判据文档（上游建议仅在反代上游为第三方时启用）。

## 🧾 账号额度合并口径（v1.9.2，PR #145）

- **仅共享额度的账号不再被误判成「额度不足」**（此前国际区部分账号因此显示异常）；
- 账号行主数字展示 **个人额度 + 成员共享额度** 的剩余与总额，已用量与来源单独标注；不限量/不可用/未知值语义明确；
- 排序同步采用合计口径（此前按个人额度排，与展示不一致）。

## 🐤 新模型可见（v1.9.2，#144）

- 官方 app 独有的对话模型（如 QoDuck）现在能被网关发现并出现在模型库/面板里（之前只有 chat 段的模型可见）。
