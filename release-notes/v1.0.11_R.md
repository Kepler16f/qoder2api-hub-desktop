# 1.0.11_R — 安全审计修复 + 会话与缓存修正（网关 2026.11.04.1_upstream）

自 v1.0.10_R 以来的全部改进：并入上游 v1.7.14–v1.7.23 共 12 提交。核心是**一次安全审计批次**（#131）、**会话身份与缓存命中修正**（#128/#136）和**积分可见性**（#129 系列）。

## 🔒 安全审计修复（#131 + 66 条行为级回归）

外部审计发现六项问题，全部修复并配上行为级回归套件（起真实 HTTP 路由复现攻击路径、每组带正向对照）：

- **Web 工具（web_search / web_fetch）绕过授权**：此前推理前不做封禁/Key 白名单/跨区预检——现在统一走模型预检，且**每轮记账**（账号/Key/模型），多轮 usage 合计回给客户端；
- **SSRF 三条绕过**：IP 全局单播判定（内网/链路本地地址拒绝）、解析结果钉死连接（防 DNS 重绑定）、重定向逐跳校验、代理不再豁免；
- **匿名注销**：`/panel/logout` 此前未认证即可调用（revoke_all 会把所有已登录浏览器踢下线）——现在先认证再吊销；
- 白名单回写丢失（设置往返丢 models/note）与保留 uid 覆盖配置被吞（导入明确拒绝 + 落盘再挡）。

## 💬 会话身份与缓存命中修正（#128 / #136）

- **一次对话不再被拆成 N 条**（#128）：此前每请求新造会话身份，一个 agent 回合的几十次工具步进被记成几十条不足 1 分钟的对话，**撞 code 110 日上限**。现在同一回合复用同一身份，会话按「一次提问」切分（#128 后续），`QD_CONVERSATION_SHARE=0` 可关。
- **缓存 98%↔0% 抖动修复**（#136）：修正上述改动引发的每轮新提问缓存归零问题——用量归组按提问、上游缓存键（session_id）按窗口，二者分离；同一段历史的价格不再差 12 倍。
- 账号亲和键不受 system 提示词每轮变化影响（只用「模型 + 首条 user」），会话粘性更稳。

## 🧾 积分可见性（#129 系列）

- **积分三段拆分**：最近请求新增「积分拆分」列（名义成本/缓存/输出三段，悬停明细）+ 本页合计；
- **全价请求统计**：超长 prompt（≥100K）且缓存为 0 的请求单独计数（这是最贵的一类调用），面板「用量洞察」新增卡片 + 降本建议；
- `cached_reported` 标记区分「真零命中」与「上游没回报缓存数据」。

## 🔧 其它

- **思考档位 clamp 双向就近**（#126）：medium 不再被单向压到 low；
- **namespace/MCP 工具展开**（#127）：递归展开（深度 4）、回程还原、合并 `additional_tools`；
- **账号测试探活改免费模型**（#134）：默认用 `price_factor==0` 的免费模型（实测 Qwen3.8-Flash），零额度号也能测出凭证好坏；**额度/排队类失败不再给账号叠冷却**（连点两次测试不会再把号压住）；
- **账号测试诊断增强**（#123 后续）：失败回包带上游 detail 与按业务码的人话 hint（10605 排队 / 112 额度 / 110 次数上限 / 430 版本 / 凭证过期）；`/diag/vm` 分两行显示「本地硬件」与「官方风控」判定来源；
