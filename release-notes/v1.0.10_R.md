# 1.0.10_R — 工具调用可靠性 + Kimi 计费归因修复（网关 2026.11.01.1_upstream）

自 v1.0.9_R 以来的全部改进：并入上游 v1.7.11–v1.7.12 共 12 提交。上游这批修复的实测现场就是本机网关的生产日志——对 coding agent 用户（Zcode / Claude Code 等）是直接可感的可靠性提升。

## 🔧 工具调用静默中断根治（#120 / #124 / #116）

- **半截 tool_calls 不再被当正常结束**：上游在工具参数没写完时干净断流，代理此前照原样转发收尾——客户端拿到「半截调用 + 没有 finish_reason」，coding agent 把它当这一轮正常结束，**整轮任务静默中断**。现在改为明确失败（EmptyToolEcho），客户端据此重试。
- **DSML 协议残片不再当正文补发**：5 处「认不出就补发」的 fail-open 出口逐个堵死（实测出现过 4828 字符的协议残片被解析进工具参数）；先剥代码围栏再判定，避免把「讲解协议的示例」误判成泄漏。
- **chat 流式出口保留同帧 tool_calls 起点**（#124）：此前合成正文帧时把同一帧里的 `tool_calls`（含 `function.name`）整帧丢掉，下游 ai-sdk 系收尾抛 `tool call delta is missing id or name` 整轮作废——现在原样搬运，无名调用先扣住、name 到手合并发出。
- **Anthropic 流式 tool_use 首帧缺 name**（#116）：`content_block_start` 缓冲到 name 已知才发；流结束仍无名则丢弃该块并降级。

## 🧾 Kimi 计费归因修复（#119）

- 官方 CLI 请求体的 `business` 块带 `model_key`，上游计费读它；网关此前不发 → **kmodel_latest 被后台静默记成 auto**。修复后计费归因正确。
- 配套**动态显示名解析**：官方改显示名（Kimi-K3 → Kimi-K3.1-Pro）的窗口期，客户端用新名请求不再被静默按 auto 路由（别名 → 冻结快照 → 动态清单三级解析，离线兜底不出网）。
- 支持 catalog-v7（官方 1.1.81+ 写 v7，与 v6 同为 QMC v1）。

## ⚠️ 移除「计费自检」（#121，重要变更）

- v1.0.9_R 搭载的**「自检」按钮已按上游实测移除**：进一步实测发现上游对网关身份**所有模型统一回报 `auto`**（该字段根本不携带计费信息），按钮的判断前提不成立，留着只会误导。
- 计费归因的正确性由 #119 的 `business.model_key` 修复保证（本版同步搭载）。

## ⚡ fork 性能补丁（本版独有）

- 装了官方 Qoder 客户端的机器上，模型目录的 QMC 解密实测耗时 14 秒，而上游的节流窗口只有 60 秒——**每分钟第一个请求都会卡顿**。本版把解密结果落盘缓存（7 天 TTL）：缓存命中 0.02 秒，重解密至多 7 天一次；并跳过官方写入模式的半成品临时目录。后续整理后反哺上游。
