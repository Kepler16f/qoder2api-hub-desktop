# 1.0.15_R — 并行工具调用修复 + 容器优雅退出（网关 2026.11.16.1_upstream）

自 v1.0.14_R 以来的变化：并入上游 **v1.9.9**（2 个修复）。桌面客户端的形态、内嵌看板、托盘与设置区全部保持不变。

## 🔧 并行工具调用 index 复用修复（PR #157）

- **现象**：上游把**不同 tool call（不同 id）复用同一个 wire index=0** 下发时，网关的流式守卫与非流式聚合会把它们当成同一个调用互相覆盖——并行的多个工具调用会丢失、参数串位（Claude Code / ai-sdk 这类多工具并发场景最容易踩到）。
- **改法**：新增 `_sse_normalize_tool_call_indices()`——按 **call id** 维护槽位映射，把复用的 index 重编成独立槽位；插桩在两处入口：**流式出口**（工具调用守卫链最前）与**非流式聚合**。
- **约束保留**：帧未被改时**保持原字节**（不重序列化）；**无名调用与截断参数仍明确失败**——不猜测补齐、不伪造参数执行。
- **回归**：新增 172 项离线断言（复用/缺失 index、分片参数、迟到 id 字段、交错顺序、非流式聚合）。

## 🧯 容器 PID 1 的 SIGTERM 优雅退出（#156）

- **现象**：容器里 Python 是 PID 1，默认不处理 SIGTERM → `docker stop` 要等满宽限期再被 SIGKILL（退出码 137），atexit 与 PID 文件清理全部不执行。
- **改法**：新增 `serve_http_server()`——**仅主线程**注册 SIGTERM，收到 TERM 抛 `SystemExit(0)` 让 serve 循环自然解卷，finally 里关闭监听并恢复原处理器；**绝不在信号处理器里调 `HTTPServer.shutdown()`**（它等的是同一线程的 serve 循环，必死锁）；清理期间重复 TERM 不打断关闭，Ctrl+C 行为不变。
- **对桌面版的影响**：**无**。桌面壳把网关跑在子线程里（不注册信号处理器），优雅停机仍走跨线程 `shutdown()`，行为与从前完全一致。
- **配套**：Docker 发布流水线改用真实 `docker stop` 验证（要求退出码 0 且不等满宽限期）。
