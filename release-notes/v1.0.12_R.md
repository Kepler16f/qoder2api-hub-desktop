# 1.0.12_R — 错误分类修正 + 504 换号 + 积分构成拆分（网关 2026.11.06.1_upstream）

自 v1.0.11_R 以来的全部改进：并入上游 v1.7.24–v1.8.0 共 15 提交。对日常使用影响最大的三件事 —— **排队/额度错误不再被客户端显示成「API 密钥无效」**、**首字超时换号不再拖到客户端 idle 超时**、**积分构成拆成四类能看清钱花在哪**。

## 🔧 排队/额度错误不再被误判成 Key 无效（#137）

- **现象**：上游排队（10605）与额度（112/110）的提示里夹着信封层的 `"code":"403"`，而不少客户端按错误**文字**归类，第一条规则就是 `/\b(?:401|403)\b/ → AUTH` —— 于是界面显示成「API 密钥无效」，用户误以为要换 Key。
- **处置**：详情里独立的 401/403 改写为 `HTTP_401`/`HTTP_403`（下划线让规则不再命中），文末附客户端认得的英文原因（排队 → rate limit、额度 → quota exhausted、次数上限 → usage limit reached），这类错误对客户端统一回 **429** 而不是 401/403。
- **fork 侧**：错误帧的 type 保持本仓白名单值（排队 `no_capacity`、额度 `quota_limit`、付费墙 `upstream_paid_wall`）—— 这些才是 Zcode 的归类依据；并顺带修掉一处**自 v1.0.9_R 起遗留**的同类问题：排队超预算的错误帧 type 此前仍是上游的 `upstream_queued`（白名单只覆盖了文案层、没覆盖错误帧），Zcode 遇到会判成 unknown 整回合判死。

## ⏱ 首字超时换号 + 坏参数先修（#137b）

- 上游 worker 迟迟不产首 token 时，同账号立刻重试几乎必然再超时，只会把客户端拖到 idle 超时（现场 14 轮 504、每轮 4–5 分钟）。现在**直接换号**（换 worker 才有意义）。
- 工具调用参数的内层裸引号 / 尾随逗号等小瑕疵，**先尝试修复再重发**；修不好仍然 fail-closed（不静默当成功）。

## 🧾 积分构成四类拆分（#141）

- 面板「额度构成」区块：套餐内 / 资源包 / SOTA / 共享池四类分开显示，含最近到期时间与来源端点；账号行下方直接内联构成明细。
- **合计修正确**（SOTA 实际在 `dedicatedResourcePackages` 里，此前被漏计 —— 合计 1800 应为 3761）。
- 新增额度端点**自动探测**（命中来源写入本地，下次直接用）；老网关 404 时提示升级而不是报错。

## 🔧 其它

- **伪 XML 工具调用回读**（#140）：识别 4 种伪 XML 形态并宽松解析参数，chat / Responses / Anthropic 五条出口全覆盖（含防误伤守卫）。
- **会话缓存保温**（可选 `QD_CACHE_KEEPALIVE`，默认关）：上游隐式前缀缓存约 5 分钟闲置过期，闲置后首发会全量重写（0% 命中、全价积分）；开启后网关在闲置临界点用同 payload 发一个最小请求续期（前缀逐字节相同即命中）。只存内存不落盘，保温请求以 `key_id=keepalive` 记账、面板可见可审计。
- **v1.8.0 性能与图片转换超时恢复**：网关性能优化 + 图片转换超时的重试预算（HTTP 与 SSE 共享一次重试额度，不会把慢转换按账号池放大）。
- 新增「Dockerfile 模块覆盖」回归测试：按 import 推导必需模块并与 Dockerfile 比对，防止再出现新模块漏打包导致镜像构建失败。
