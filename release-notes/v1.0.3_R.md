# 1.0.3_R — 并入上游 v1.3.5–v1.3.7（网关 2026.10.14.2–6）

本版把上游连续发布的三个版本（四个报告问题修复、双区自动路由、路由决策可观测）与一批 UI/测试基建全部并入，并沿用新版本线（桌面 `1.0.x_R`、网关 `日期.序号_upstream/_re`）。

## 🧲 并入上游（网关 2026.10.14.2–5_upstream）

- **v1.3.5 四个报告问题**：额度账本守卫（#25，无守卫写入不再拿 0 覆盖健康余额）、Windows 代理修复（#27，每请求现建 opener 不再固化首次代理配置——与 fork 的传输收口融合，见下）、双区冷却作用域（#29，单号区域不再被错误长冷却）；≤10s 频控改为**等待后重试**（客户端看到延迟成功而非 429）；社区 PR：Anthropic 入口思考档位（effort）静默丢失修复、上游非对象帧不再崩流
- **v1.3.6 双区自动路由**：只存在于单区的模型自动路由过去；当前区无可用账号时试另一区；面板三态开关（自动/锁国内/锁国际）；切换发生时响应带 `X-Qoder-Realm` + 原因；显式指定（参数/Key 绑定/头部）永不被覆盖
- **v1.3.7 路由决策可观测**：用量行持久化实际出口与原因，面板显示确定陈述而非猜测
- 发布后杂项：**看板 UI 采纳 wb webui 模式**——`data-theme` 深色体系（默认跟随系统 + 手动切换下拉）、分页导航、工具栏减负；测试套件输出指纹、独立 tests 工作流

## 🔧 fork 手术（2026.10.14.6_re）

- **传输收口融合**：上游新收口函数 `_opener_for_request()` 直接委托 `UPSTREAM_OPENER` 单例——`QD_PROXY_UPSTREAM_PROXY` 钉死优先、env-only 代理（采纳上游 #27 语义，不读注册表）、`UpstreamOpener._stub` 测试注入点继续覆盖全部出站
- 信封错误路径融合：上游的实际冷却捕获 + `realm_ready` 日志，与 fork 的付费墙（112）模型冷却、额度自动刷新钩子共存
- 流式心跳保留（fork 特性，防大请求建连期客户端超时）；自动路由的 `X-Qoder-Realm` 头在流式响应上不可见（SSE 头先于路由决策发出，属设计约束），用量行仍会记录实际出口
- 看板深色体系换用上游 `data-theme`（fork 的 `prefers-color-scheme` 覆盖块退役，功能等价且覆盖面更全）

## 📦 下载与安装

| 文件 | 适用 |
|---|---|
| `Qoder2API-Hub-setup-windows-x64.exe` | Windows 10/11 x64（按用户安装，无需管理员） |
| `Qoder2API-Hub-setup-windows-arm64.exe` | Windows on ARM（原生） |
| `Qoder2API-Hub-macos-arm64.dmg` | Apple Silicon Mac |
| `qoder2api-hub-linux-x64.deb` | 主流发行版 x64（内嵌用系统 WebKit2GTK） |
| `qoder2api-hub-linux-arm64.deb` | ARM64 Linux（同上） |

- Windows：双击安装（SmartScreen 提示时「更多信息 → 仍要运行」）；静默部署 `...setup.exe /VERYSILENT /LANG=chinese`
- macOS：DMG 拖入 Applications，首跑右键打开；仍被拦则 `xattr -cr /Applications/Qoder2API-Hub.app`
- Linux：`sudo dpkg -i qoder2api-hub-linux-*.deb`（依赖系统 WebKit2GTK，dpkg 自动安装）
- 首次看板密码 `admin`，请立即修改
