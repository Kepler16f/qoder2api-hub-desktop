# 1.0.7_R — 思考模型保正文 + 并入上游 v1.6.2–v1.7.6（网关 2026.10.22.3_re–2026.10.28.1_upstream）

自 v1.0.6_R 以来的全部改进一次搭载：核心是**思考模型正文不再被 reasoning 饿死**（2026.10.22.3_re）与 **Claude Code 思考强度不再被丢**（2026.10.22.4_re），外加上游两个批次共 44 个提交并入（排队可见、启动防双开、账号判定统一、官方积分消耗、看板重做等）。

## 🧠 fork 自有修复（思考链路）

- **思考模型保正文**（网关 2026.10.22.3_re）：客户端未给 `max_tokens` 时，思考模型自动补 81920 输出上限（`QD_REASONING_MODEL_MAX_TOKENS` 可调）。此前 BASEPROMPT 默认 32768 对思考模型偏小——reasoning 把预算烧完，正文被饿死（实测 90K 输入只回 ~200 字）。客户端显式传的 `max_tokens` 一律尊重。`enable_thinking` 顶层开关上游不认且干扰，网关不再处理（关思考请用 `reasoning_effort=none`，none 不再被吞）。
- **Claude Code 思考强度送达**（网关 2026.10.22.4_re）：ccswitch / Claude Code 经 `/v1/chat/completions` 发 adaptive thinking（`thinking.type=adaptive` + `output_config.effort`）时，此前只认 `reasoning_effort` / `reasoning.effort` / `thinking.effort` 三种写法，**指定强度被静默丢弃、固定跑默认档**（ccswitch 全线 `client_effort=None` 实锤）。补齐第四种提取，与 Anthropic 入口 `effort_from_anthropic` 口径对齐；线上验证 `low` 送达。

## 🔄 并入上游 v1.6.2–v1.6.13（网关 2026.10.23.1_upstream · 21 提交）

- **#75 出站身份对齐官方**：设备码优先取原生 UMID（`runtime-info.exe` + 同目录 `sgsdk.dll` 双文件语义）——桌面发行版的 spec 已补打 sgsdk.dll，不装官方客户端也有真实机器身份。
- **#76 / #83 自动换区修复**：三入口未指定出口时不再钉死当前区（独占模型跨区请求不再被误判 400）；跨区 failover 死循环修复（另一区先按实际出口解析 + 每请求单次切换守卫）。
- **#86 账号测试钉号**：面板「测试」必须落在被点的那个账号上（此前会落到池里任意账号，测试结果张冠李戴）。
- **#87 排队可见**（⭐ 体感最大）：模型排队不再直接 502——默认 `visible` 模式下 SSE 流内持续发排队进度提示帧直到开流（`QD_QUEUE_WAIT_MODE=fast` 切回快速失败）；Responses 回读链与兼容字段补齐；`/health` 增 quality 指标；`#85` bat 空格路径修复。
- 用量洞察（`qoder_pricing` / `qoder_activity`）+ 本地 web 工具（`web_search` / `web_fetch` 由网关本地执行，`/settings/web-tools` 开关）。

## 🔄 并入上游 v1.6.14–v1.7.6（网关 2026.10.28.1_upstream · 22 提交）

- **#89 启动防双开识别垂死实例**：`/health` 回 `pid`/`started_at`；旧实例正在退出时不再误拦新启动；bind 失败重试 3 次并复查。附带 macOS/Linux 官方停止脚本 `stop-qoder-proxy.sh`（僵尸进程视为已退出、防误杀）。
- **#90 企业/团队账号判定统一**：组织字段 > userType > 共享额度池（此前 userinfo 不返回 user_type，企业号漏判导致团队闸门/共享额度不生效）；面板企业徽标。
- **#99 Anthropic 入口排队可见**：与 chat/responses 对齐（此前 anthropic 排队零等待 503 且丢 Retry-After）。
- **官方积分消耗**：跟进官方桌面端新版，`credits-summary`（累计/峰值）+ `credits-heatmap`（近 365 天逐日）真实记账口径进面板；intl 第二活动入口（`center.qoder.sh`）。
- **#98 看板轮询去闪烁**：分区签名，数据没变不重播动画/不重建 365 天热力图节点。
- **#100 排队耗尽不再截断流**（网关 2026.10.26.2_upstream）：排队超预算返回的 `RateLimited` 没有 `.status` 字段，收尾路径裸读会抛 AttributeError、把 HTTP 200 的流硬生生截断（客户端表现为「转一半就没了」）。新增统一的异常→状态码取值，排队耗尽按 429 收尾并按协议发终态事件。
- **#101 max_tokens 上限自动学习**：客户端报「max_tokens 超出范围」时，网关从上游错误信息里学到该（区域, 模型）的真实输出上限并落盘缓存（7 天），之后组包时自动 clamp，`/v1/models` 补 `max_output_tokens` 字段——客户端不必再猜。
- **v1.7.1 数据看板重做**：账号独立页、KPI/排行/趋势新版统计页（fork 独占的桌面客户端设置区与局域网访问逐字节保留）。
- **opt-in 前缀会话亲和**（默认关闭）：`QD_SESSION_CACHE=memory|redis` 时按「消息前缀」复用上游 session_id，提升 prompt cache 命中率；只存哈希不存对话正文。
- **一键更新未收录**（红线维持）：上游的网关自更新（`qoder_updater.py` / `/update/plan` / `/update/apply` / 看板按钮）整块剔除——其 REPO 硬编码上游仓库，自拉 tarball 会把 fork 文件换成上游原版；桌面版更新通道是安装包（看板「检查更新」按 APP_VERSION 对比本仓库 tag）。
